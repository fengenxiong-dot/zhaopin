# 招聘信息管理系统 V1 开发计划

| 项目 | 内容 |
|---|---|
| 计划版本 | V1.0 |
| 对应产品文档 | V1.1 业务基线 |
| 对应技术设计 | V1.0 推荐技术基线 |
| 更新日期 | 2026-08-27 |

## 1. 开发策略

采用“按业务闭环逐步交付”的方式，不先建设所有基础设施后一次性交付。

每个阶段均应包含：

1. 数据库迁移
2. 后端接口
3. 前端页面
4. 权限校验
5. 操作留痕
6. 自动化测试
7. 业务验收

## 2. 里程碑总览

```mermaid
flowchart LR
    M0[阶段0 技术准备] --> M1[阶段1 用户权限与字典]
    M1 --> M2[阶段2 招聘需求与推荐工作量]
    M2 --> M3[阶段3 候选人及初复试]
    M3 --> M4[阶段4 Offer报到与待办]
    M4 --> M5[阶段5 数据看板与导出]
    M5 --> M6[阶段6 历史数据迁移]
    M6 --> M7[阶段7 验收部署]
```

## 3. 阶段 0：技术准备

### 目标

建立可持续开发、测试和部署的工程基础。

### 任务

- 确认服务器、Docker、PostgreSQL、域名和 HTTPS 条件。
- 初始化 Git 仓库及分支策略。
- 初始化 Vue 3 + TypeScript 前端。
- 初始化 FastAPI + SQLAlchemy + Alembic 后端。
- 建立 PostgreSQL 开发数据库。
- 建立 Docker Compose 本地环境。
- 配置代码格式、静态检查和测试命令。
- 配置开发、测试、生产环境变量模板。
- 建立统一异常格式和请求追踪 ID。
- 建立基础日志和健康检查接口。

### 验收

- 新成员可按说明在本地启动完整环境。
- 前端可以调用后端健康检查。
- Alembic 可以创建和回滚测试数据库结构。
- 自动化测试命令可运行。

## 4. 阶段 1：用户、权限与业务字典

### 目标

形成系统登录、角色和基础数据管理能力。

### 后端

- 用户、角色、用户角色、组织架构表。
- 登录、退出、当前用户接口。
- 密码哈希及账号禁用。
- HR、招聘管理者、系统管理员权限框架。
- 字典类型与字典项接口。
- 审计日志基础能力。

### 前端

- 登录页。
- 应用外壳与导航。
- 用户管理页。
- 组织架构页。
- 字典管理页。
- 无权限和会话过期处理。

### 测试

- 三种角色访问矩阵。
- 禁用账号无法登录。
- 后端权限不可由前端绕过。
- 字典停用不影响历史展示。

### 验收

- 管理员可以创建用户并分配角色。
- 普通 HR、管理者和管理员登录后看到不同功能范围。

## 5. 阶段 2：招聘需求与简历推荐工作量

### 目标

完成从创建需求到 HR 录入每日推荐数字的闭环。

### 后端

- 招聘需求表和参与 HR 表。
- 需求创建、编辑、分配、完成和关闭接口。
- 推荐工作量表及唯一约束。
- 普通 HR 数据范围校验。
- 需求列表筛选和分页。
- 推荐量汇总接口。

### 前端

- 招聘需求列表。
- 新建和编辑需求。
- 多 HR 分配。
- 需求详情概览。
- 简历推荐快速录入。
- 个人推荐记录查询。

### 测试

- 一个需求可以分配多名 HR。
- 未参与需求的 HR 无法录入推荐数。
- 同日、同需求、同 HR、同渠道重复记录提示合并或修改。
- 推荐数必须为正整数。

### 验收

- 管理者创建需求并分配多名 HR。
- 每名 HR 可以独立录入自己的推荐数量。
- 管理者可以按日期、需求和 HR 查看推荐工作量。

## 6. 阶段 3：候选人、编号、初试与复试

### 目标

完成候选人建档和初复试主流程，这是 V1 的核心阶段。

### 后端

- 年度候选人编号序列。
- 候选人和应聘记录。
- 联系记录。
- 面试记录。
- 状态机领域服务。
- 初试和复试动作接口。
- 待定和 Out 逻辑。
- 流转事件和乐观锁。
- 候选人转交接口，仅管理者使用。
- 合格数和推荐通过率计算。

### 前端

- 新增合格候选人弹窗。
- 候选人列表和筛选。
- 候选人看板。
- 候选人详情及时间轴。
- 联系记录。
- 初试预约和结果弹窗。
- 复试预约和结果弹窗。
- 待定跟进。
- 终止流程弹窗。

### 测试

- 编号按年份顺序生成且并发不重复。
- 普通 HR 只能看到自己负责的候选人。
- 不允许跨阶段推进。
- 直接拒绝邀约与预约后未到场分别记录。
- 待定必须填写原因和跟进日期。
- Out 必须填写阶段、主动方和原因。
- 两人同时更新时后一请求得到版本冲突。

### 验收

- 可以完成建档、初试、复试、待定和任一阶段 Out。
- 所有动作均出现在候选人时间轴。
- 推荐工作量中的合格数自动更新。

## 7. 阶段 4：Offer、报到、需求暂停与站内待办

### 目标

完成复试通过到实际入职的闭环，并实现日常工作台。

### 后端

- Offer 沟通数据。
- 外部审批状态：审批中、通过、不通过。
- Offer 发送、接受、拒绝和失效。
- 报到、延期和实际入职。
- 需求暂停和恢复批量冻结。
- 待办表、事件生成和定时扫描 Worker。
- 工作台汇总接口。

### 前端

- Offer 沟通和审批状态弹窗。
- Offer 发送与回复记录。
- 待报到和延期操作。
- 工作台数据卡片。
- 我的待办列表。
- 需求暂停和恢复确认。
- 冻结候选人状态展示。

### 测试

- 审批不通过后候选人正确终止。
- Offer 发放、接受和入职日期顺序校验。
- 延期保留原日期历史。
- 需求暂停后所有在途候选人不可推进。
- 需求恢复后正确恢复状态或生成重新确认待办。
- 同一待办条件不会重复生成。

### 验收

- 可以完成复试通过、Offer、报到和入职闭环。
- HR 登录后可以看到当天需要处理的事项。
- 需求暂停能冻结全部在途候选人。

## 8. 阶段 5：数据看板与导出

### 目标

实现管理者关注的工作量、漏斗、HR 对比和效率分析。

### 后端

- 工作量聚合。
- 招聘漏斗。
- 按发生时间和按推荐批次两种口径。
- 多 HR 对比。
- Out 原因分析。
- 招聘效率和阶段停留时间。
- 需求完成率。
- 数据导出任务。

### 前端

- 统一看板筛选器。
- 个人工作量卡片和表格。
- 漏斗图。
- 多 HR 对比图表。
- Out 阶段与原因排行。
- 效率指标。
- 明细下钻。
- Excel 导出入口。

### 测试

- 每个指标可追溯到事实表和明细。
- 两种时间口径结果符合定义。
- 待定不误算为通过或失败。
- 暂停时长从有效周期中扣除。
- 普通 HR 不能通过看板或导出获得他人数据。

### 验收

- 管理者可以选择日期、HR、需求、公司、部门和渠道。
- 可以同时选择多名 HR 进行比较。
- 漏斗每层可以下钻到候选人明细。

## 9. 阶段 6：历史数据迁移

### 目标

迁移 2026 年 1 月以来的招聘数据，并保证可核验、可回查。

### 后端与工具

- 迁移批次和原始行暂存表。
- Excel 文件解析。
- 公司、部门、岗位、渠道、HR 和状态映射。
- 候选人阶段匹配。
- 年度编号生成。
- 原始备注全文保存。
- 待核验数据处理。
- 分月对账报告。

### 前端

- 迁移批次列表。
- 导入进度。
- 待核验记录列表。
- 映射修正。
- 对账结果。

### 范围

- 迁移社招主流程数据。
- 劳务外包只进入原始暂存层，不进入 V1 业务表。
- 不迁移任何邮箱或招聘平台账号密码。

### 测试

- 同一文件不会重复导入。
- 原始文件、工作表、行号可追溯。
- 长备注完整、不截断。
- 无法可靠合并的记录不会被强制合并。
- 分月总量可与原 Excel 核对。

### 验收

- 至少完成 2026 年 1 月以来全部主流程数据导入。
- 待核验记录有明确处理入口。
- 原始 Excel 保持不变。

## 10. 阶段 7：业务验收与生产部署

### 目标

完成正式上线前的安全、数据、性能和业务验收。

### 任务

- 执行完整业务回归。
- 使用真实业务样例验收每条状态分支。
- 校验权限与导出范围。
- 执行数据迁移演练和回滚演练。
- 完成数据库备份与恢复演练。
- 配置 HTTPS、域名和生产环境变量。
- 配置日志、监控和备份任务。
- 编写管理员和 HR 使用说明。
- 准备上线切换方案。

### 验收

- V1 产品文档中的验收标准全部通过。
- 关键流程自动化测试通过。
- 历史数据总量对账通过或有已批准差异说明。
- 备份可以成功恢复。
- 生产账号与初始管理员已准备。

## 11. 建议的测试数据集

开发过程中至少准备以下候选人样例：

1. 正常完成初试、复试、Offer并入职。
2. 简历合格后拒绝初试。
3. 接受初试但未到场。
4. 初试待定后通过。
5. 初试不通过。
6. 复试待定后不通过。
7. Offer沟通失败。
8. 外部审批不通过。
9. Offer发出后拒绝。
10. 接受Offer后放弃报到。
11. 延期一次后入职。
12. 需求暂停期间被冻结，恢复后重新预约。
13. 被管理者转交给其他HR。
14. 与现有候选人疑似重复但继续创建。
15. 从历史Excel迁入且备注很长。

## 12. Definition of Done

一个功能只有同时满足以下条件才算完成：

- 业务规则与产品文档一致。
- 权限在后端正确校验。
- 数据库变更有 Alembic 迁移。
- 关键业务动作有操作留痕。
- 正常路径和异常路径测试通过。
- 前端有加载、空数据、错误和无权限状态。
- 接口文档更新。
- 不引入明文密码、密钥或账号凭据。
- 相关验收用例通过。

## 13. 开发优先级

### P0：必须上线

- 登录和三种角色
- 招聘需求及多 HR 分配
- 简历推荐数字录入
- 合格候选人建档和年度编号
- 初试、复试、Offer、报到状态机
- Out 原因和备注
- 一人负责到底的数据权限
- 操作时间轴
- 需求暂停冻结
- 站内待办
- 核心工作量和招聘漏斗
- 2026 年历史数据迁移

### P1：V1 内尽量完成

- 多 HR 对比图表
- 效率指标
- 数据导出
- 疑似重复提示
- 迁移核验页面

### P2：后续版本

- 再次应聘和人才库
- 劳务外包独立类型
- 企业微信或邮件通知
- 招聘平台接口
- 面试官直接录入
- 在线 Offer 审批
- 更细字段权限

## 14. 项目管理建议

- 每个阶段完成后用真实招聘案例进行业务演示。
- 状态机、权限和指标公式的变更必须同步更新产品文档和测试。
- 不在开发中通过临时字段绕过状态机。
- 历史迁移脚本和业务系统使用同一套状态、字典和编号服务。
- 看板数据与明细不一致时，以事实表和业务事件为准，不手工修改看板结果。

## 15. 已确认的开发输入

- 生产环境：Linux。
- 基础设施：允许 Docker、Docker Compose 和 PostgreSQL。
- 访问方式：内部域名。
- 用户开通：系统管理员手工创建。
- 附件：服务器本地持久化目录。
- 版本管理：已有 Git 远程仓库，但当前工作区尚未连接远程地址。

阶段 0 剩余外部输入仅为 Git 远程仓库地址；内部域名、HTTPS 证书和生产附件容量可以在部署阶段补齐。
